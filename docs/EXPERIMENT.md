# 実機実験の手順

この手順の結果は未取得です。測定値・カード型番・実物の版数・ファームのコミットを `reports/raw/<実験日時>/` に残してください。このフォルダはGit管理対象外です。

## 1. 接続・書き込み

1. 対象が**Pico 2 W搭載P-MAIN**であること、SonyマルチIMU Add-onの型番を確認する。
2. JP1=3.3V、JP10 pin1–2開放、D02→J_SPR1.1、D01→J_SPR1.2、GND→J_SPR1.3を確認。外付けGNSSは未接続。
3. P-PWR→P-MAINの電源6芯/I²C5芯の向き、V3D=3.3V、V5D=5Vを確認。元基板のBRINGUP手順を優先する。Pico USBだけで周辺回路へ給電できると考えない。
4. TX基板を接続する場合もこのファームのGP16はLow固定。元基板の指示どおり電源投入順序を守る（SW_TXの活線操作を避ける）。
5. 両SDはまずFAT32のカードを使用する。既存ファイルをバックアップしたカードで試す。このファームはフォーマットしない。
6. 接続ポートを読み取り、P-MAINとSpresenseへそれぞれ対応するファームを書き込む。初回Spresenseのブートローダー設定はSony公式手順に従う。
7. Picoのボタンを離して起動する。両USBモニターを115200で記録する。

2026-09-19の準備時点ではCOM6にUSB Picoが見えましたが、親機か子機かは未確認です。SpresenseのUSBは見つかりませんでした。**この情報だけでCOM6へ自動書き込みしないこと。**

## 2. SD単体：屋内でも可能

両方で `SD_READBACK_OK` を確認する。これは512バイトの書き込み・保存確定・開き直し・読み戻し一致を意味します。エラーならカード・電源・接触を調べます。

60秒記録し、両方へ `q` を送って停止。Picoは約600行、Spresense IMUは約7,200行、GPSは約60行が目安です。起動時間を含むため厳密一致ではなく、実際の `mono_us` / `received_mono_us` の期間で評価します。両SDのファイルをPCにコピーし、`verify_logs.py` で行CRC32・連番・単調時刻・エラー数を検証します。GNSS未測位でもUTC=0として記録されることを確認します。

合格目安：読戻し一致、行CRC・連番エラー0、SDエラー0、IMUエラー/欠落0。IMU受信平均レート115〜125 Hz。IMUの静止値、温度、傾けたときの各軸の応答は別途確認します。

失敗後に再マウントしても累積エラーカウンターは残ります。原因を修正した後、合否判定用の試験は再起動して取り直してください。

## 3. 屋外GNSS・時刻対応

アンテナを空が見える位置に置く。コールドスタートなので測位まで待つ。3回連続のPPS/UTC対応後にUIが「PPS同期候補」、ログがsync=1になることを確認します。

Picoで一度停止→新しいログ開始し、10分記録します。PPS周期999,000〜1,001,000 µs、UART到着遅延20〜800 ms、同期候補率95%以上、通信CRC0、RX overflow0、ログ欠落0を確認します。

**精度検証はこの次に行います。** ロジックアナライザーでSpresense D02、Pico GP6、UART D01を観測し、UARTフレームのUTC秒がどのPPSに対応するかを確かめます。周期だけでなく、独立したGNSS時刻基準との比較で1秒ずれがないことも確認してください。Wi-Fiなし/あり/大きなCSV取得中の各条件でPPS捕捉のジッターと連続性を測ります。要求精度（例：最大誤差100 µs以内など）は実験目的に合わせて先に決め、測定器の分解能・誤差も記録します。

`pps_period_us` は割り込み捕捉周期であり、D02に対する割り込み遅延そのものではありません。遅延を測る場合は計測用GPIOやハードウェアキャプチャを追加し、使用ピンとファーム変更を記録してください。

## 4. 異常時の挙動

- PPS線を外す：最後の確定アンカーから1.5秒を超えて同期表示が残らず、UTC=0に戻ること。
- UART線を外す：同様に古いUTCを確定値として出し続けないこと。受信再開後は3回の連続対応を待つこと。
- GNSSが測位できない状態：記録は続き、未確定の表示になること。
- Spresenseを再起動：連番リセットから再捕捉すること。異なる起動セッションのIMUログを連続サンプル扱いしないこと。
- SD未挿入で起動：取得・通信は継続し、SD失敗を表示すること。故障試験で通電中に抜く場合は破損してもよいテスト用カードを使い、通常の運用では停止後に抜くこと。

## 5. 無線・エクスポート・メモリ

スマホをAPに接続し `http://192.168.4.1/` を開く。電圧・電流をテスターの値と比較する。Wi-Fi越しの取得中も `missed_rows` と `rx_overflows` が増えないことを確認する。

過去ログの取得、現行ログの停止→取得、新規ログの開始を試す。現行ログは記録中の取得が409で拒否されることを確認する。取得したCSVとカードからコピーした同名CSVのSHA-256が一致することを確認する。

30分以上、接続・切断・ダウンロードを繰り返してヒープ残量が減り続けないこと、最小値に十分な余裕があることを確認する。フラッシュ/RAMの静的使用量だけで実行時余裕を判定しないでください。

## 記録する項目

実物の基板版数、IMU型番、電源電圧、カード型番/容量/フォーマット、ファームcommit、GPS測位までの時間、測位衛星数、試験時間、CSVのSHA-256、各エラー数、PPS対応確認方法、時刻誤差の最大/平均/分散、無線あり/なしの差、ヒープ最小値。
