# 時刻同期方式と精度の検証

## 同期の流れ

Spresense内蔵GNSSからD02へハードウェア1PPSを出力し、Pico GP6の立ち上がり割り込みで64 bitの起動後マイクロ秒を記録します。D01→GP7では1秒ごとにGPSのUTC・座標・状態を64バイトのCRC32付きフレームで送ります。PicoはUARTの到着時刻そのものをUTCの秒境界には使いません。

Picoのcore1がPPSとUARTだけを担当します。core0はSD、INA226、USB、Wi-Fiを担当。PPS割り込み内でSDや通信を行いません。Wi-Fi送信は512バイトずつ進め、SD全体をRAMに載せません。

UTCの秒ラベルを「直前のPPS」に対応させる条件は次のとおりです。

- SpresenseがGNSS由来の2D/3D測位に成功し、有効なUTC日付を返す。
- GPS測位時刻の小数部が0〜1,000 µs。
- フレーム受信完了が直前PPSの20〜800 ms後。
- 連番・UTC秒・PPS番号が3回続けてそれぞれ1ずつ増える。
- PPS周期が999,000〜1,001,000 µs内。途絶・異常周期・UTCジャンプでは再捕捉。
- 最後にUTC対応を確認したPPSから1.5秒未満。期限切れはUTC=0、sync=0とする。

サブ秒の換算は直前PPSの測定周期で補正します。最初の捕捉、再捕捉、時計補正の前後を含めて常に連続する時刻が必要な解析には、`mono_us` を使ってください。UTCは同期区間ごとに扱います。

## まだ保証していない点

**PPSとUART測位データがどの秒に対応するかを、実機で必ず確認します。** Sonyの測位通知には処理遅延があります。上の時間窓・連続性検査は破損や大きな遅延を排除しますが、毎回ちょうど1秒遅れる等の系統的な対応ずれを証明・排除できません。そのためUIは「PPS同期候補」と表示し、`sync=1` は「ソフトウェアの対応条件を満たした」という意味です。確認前にµs精度を達成したと解釈しないでください。

GPIO割り込みにも遅延とジッターがあります。要求精度が未指定のため、本実装の実測精度を数値で保証していません。ロジックアナライザーと独立した時刻基準を使い、秒の対応、Wi-Fi/SD負荷時の割り込み遅延、ドリフトを確認します。サブµs等が必要ならPIO/DMAでのエッジ捕捉とハードウェア時刻対応を追加します。

SpresenseのIMUログは `sensor_timestamp_raw`（センサー由来）と `received_mono_us`（アプリがFIFOから読んだ時刻）を保存します。**後者は取得瞬間の精密なUTCではありません。** GPSログにも同じ起動後時計を残すので概略の照合は可能ですが、IMUの精密UTC化にはセンサー時計とPPSのハードウェア対応が別途必要です。[Sony公式例](https://github.com/sonydevworld/spresense/blob/master/examples/cxd5602pwbimu/cxd5602pwbimu_main.c)の19.2MHzカウンター換算を解析に使い、CSV自体には32bit生値を保持します。差分はuint32のラップを扱います。実際のカウンター周波数精度を校正したという意味ではありません。960Hz設定時の不連続カウンターは、差分0または30000 tick超のイベント数であり、失われたサンプル総数の推定値ではありません。IMU各軸もドライバー出力をそのまま保存し、静止・既知回転の試験で単位と軸方向を確認します。

GNSS未測位中は取得・SD保存を続けますがUTCを確定しません。DS3231を代替の精密時刻源にしたり、未測位時刻を正確と表示したりしません。うるう秒（sec=60）は拒否して再捕捉します。PicoからSpresenseへのコマンド、時刻の逆送、Spresense SDの遠隔取得は現在の片方向リンクにはありません。

## 通信仕様 v1

UART 115200 bps / 8N1、64バイト固定、整数はlittle endian。座標は有効フラグと一緒に解釈します。

| バイト | 内容 |
|---|---|
| 0–3 | ASCII AQB1 |
| 4 | version=1 |
| 5 | bit0=UTC有効候補、bit1=座標有効、bit2=Spresense SD記録可能、bit3=IMU取得可能 |
| 6 / 7 | 測位モード / 測位使用衛星数 |
| 8–11 | 32 bit連番 |
| 12–19 | UTC Unix秒 64 bit |
| 20–23 / 24–27 | 緯度 / 経度、符号付き1e-7度 |
| 28–31 | 高度、符号付きmm |
| 32–35 | 測位時刻の小数部µs |
| 36–39 | IMU取得サンプル数 |
| 40–43 | IMU取得エラー数 |
| 44–47 | SDエラー＋GPSログキュー欠落数 |
| 48–51 | Spresense単調時刻msの下位32 bit |
| 52–55 | Spresense SD書き込み行数（ヘッダー2行を含む） |
| 56–59 | IMUタイムスタンプ不連続検出＋アプリキュー欠落数 |
| 60–63 | バイト0–59のCRC32/IEEE、初期・最終XOR=0xffffffff |

電源再投入で連番・各カウンターはリセットされます。Picoは対応を3秒分確認し直します。CRCは偶発的破損の検出用で、暗号認証ではありません。
