# IMU保存形式をGPS/UTC追加前へ戻す

| 項目 | 内容 |
|---|---|
| 日時 | 2026-09-21 JST |
| 目的 | ユーザー指定によりIMUへのGPS/UTC付与を撤廃し、元の保存形式へ戻す |
| 対象 | bb79e03を基に、本コミットのMainCore/SubCore1をセットで書込み |
| 判定 | 形式・ビルド検査合格、実機の記録継続を確認。GPS受信成功時のSD異常の解消は未確認 |

## 前提条件・接続

Sonyメイン＋拡張ボード、SPI5 CXD5602PWBIMU（960 Hz、4g/500 dps、FIFO閾値1）、同じSDHCIカード、USB給電。COM7のCP210x VID/PIDと既知の個体番号を照合。Sony Arduino core 3.4.7、PicoはPlatformIO。親機・子機のUSBは未検出で書込み対象外。RX、水温、水圧、LCDは対象外。SD型番、給電電圧は未測定。

| 信号 | 接続・今回の動作 |
|---|---|
| 親機UART | D01 TX→100Ω→親機GP7（物理10）、共通GND、115200 bps。送信を維持 |
| 親機PPS | D02→100Ω→親機GP6（物理9）。GNSSハードウェア出力を維持 |
| 自己PPS | D02→D03、JP1=3.3V（既報ユーザー確認）。ジャンパーは変更せずD03割り込みを無効化、入力のまま |
| IMU/SD | SPI5 Multi-IMUと拡張SDHCI、変更なし |

## 変更・手順

- IMUバッチ定義を1d92caeの11列形式へ復元。seq、電源投入後読取り時刻、センサー生タイムスタンプ、温度、角速度3軸、加速度3軸、CRCを保存する。
- IMUのUTC換算・共有ロック・UTC列を削除。追加したSpresense自身のPPS入力処理とGPSファイルのPPS追加列も撤廃した。GPSファイルのUTC・位置と親機通信は維持する。
- 960 Hz、並列CSV整形、待機なしの起動、SD診断と安全停止を維持。時計は現行のArduino micros()を維持しており、全ファームの単純な過去版への巻き戻しではない。
- ファーム書込み前だけqで正常停止を確認し、MainCore/SubCore1の両パッケージ検証・保存成功を確認。その後90秒は読取りのみで観測し、記録を止めない。
- 既存SDファイルは削除・変換せず、新規番号へ保存。

## 結果

観測終了時、IMU 93,872件、SD 93,926行。SDエラー0、IMUエラー0、ギャップ0、キュー欠落0。recording=1 / sd=1で継続中。GPS測位は未成立。

Sony両コアとPico両構成ビルド成功。新しいIMUバッチのホスト検査で11列・全行CRC・境界値・異常入力拒否を確認。Python8件と既存C++共通テストも合格。Pico実機の書込みはしていない。

[状態と集計](evidence/results.json)、[実測状態ログ](evidence/status.txt)。生ログはreports/rawのみ。今回の保存形式は[仕様書](../../docs/SPRESENSE_LOG_FORMAT.md)を参照。

## 限界

保存行数はwrite成功カウンタ。記録を継続するためSD全ログの回収・読み戻しは行っていない。GPS未測位の観測だけでは「受信成功でSDが停止する」問題の解決を判定できない。IMU行にはGPS/UTCがなくなるため、単独行から絶対時刻を直接取り出すことはできない。親機・子機の時刻同期精度は今回対象外。
