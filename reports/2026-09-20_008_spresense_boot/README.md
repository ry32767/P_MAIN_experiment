## 前提条件

COM6とCOM7を再検出。COM6は親機、COM7は前回識別したCP210x経由のSpresense。両SDは挿入済みとのユーザー申告。IMU型番・SD型番/容量・基板版数は未確認。RX、水温、水圧、テザー、LCDは未接続との申告。

設計上の配線はSpresense拡張D02→J_SPR1.1→Pico GP6（物理9）、D01→J_SPR1.2→GP7（物理10）、GND→J_SPR1.3。3.3V、各100Ω、JP1=3.3V、JP10 pin1–2開放が前提。SpresenseのSDは拡張SDHCI、IMUはSPI5を想定。実配線の確認は未完了。詳細は[配線資料](../../docs/HARDWARE.md)。

## 実施内容と結果

1. 再開指示後、識別済みCOM7を指定し、Arduino CLIの公式`burn-bootloader`（sfutools、115200bps）を開始した。今回は実行前の権限拒否はなかった。
2. 公式手順のSubCore1〜5削除、sync、再起動処理のログを確認した。これは公式初期セットアップの処理であり、SDのフォーマットではない。
3. loader/GNSS/DNN/AES/sysutil/mp3decの公式パッケージを渡すインストーラーが起動した。02:09時点でflash_writerのプロセスは生存・応答あり。`stored_version.json`はまだ存在せず、ライセンス確認とパッケージ転送の完了は確認できていない。
4. ユーザーにライセンス画面の表示状況と、同意する場合の操作を案内した。画面自体をこちらで目視確認したとはしていない。
5. 前回の128B転送成功を再利用する`flash_spresense_128.py`を用意し、Python構文確認を実施した。今回はまだこの補助ツールで転送していない。ESPKは公式SDK配置と、公式インストーラーのバージョン確認ファイルが一致する場合に限定。各パッケージのボード側検証成功を確認し、不成立なら停止する。

## 残件

ライセンス確認後、公式転送の進行を確認する。必要なら公式同梱XMODEM実装による128B転送を使う。ブートローダー、IMU、GPS、両SD保存、通信・時刻同期・精度の合格はまだ確認できていない。
