## 前提条件

接続を確認したのは親機のUSB（COM6）。ユーザーは識別のためSpresenseのUSBを一時的に取り外した。P_MAINのSDは以前の申告では挿入済みだが、今回の挿入状態・形式・容量は確認待ち。電源基板の給電、Spresense信号線、IMU型番、RTC・磁気センサ等の現在の接続は未確認。

RX基板、水温、水圧、テザー、LCDはユーザー申告で未接続。TX制御GP16はファームでLow固定。基板版数は未確認。

| 機能 | 設計上のピン | 条件・実接続の確認 |
|---|---|---|
| SD SPI | GP10/11/12/13（物理14/15/16/17） | SCK/MOSI/MISO/CS、1MHz。配線・カード状態未確認 |
| SD検出 | GP15（物理20） | Low=挿入想定、今回端子電位未測定 |
| 電源監視 | GP4/5（物理6/7） | INA226、0x40、20mΩ。給電・実接続未確認 |
| 電源起動判定 | GP26（物理31） | ボタンラダーのADC値で周辺初期化へ進む。外部電源の正常性を保証しない |
| LED / ALERT | GP2/3（物理4/5） | LED目視・ALERT機能未確認 |
| PPS / UART | GP6/7（物理9/10） | Spresense D02/D01、3.3V、100Ω直列。今回受信なし |
| TX制御 / 温度 | GP16/27（物理21/32） | Low固定 / 未使用 |

全配線の根拠は[HARDWARE.md](../../docs/HARDWARE.md)。Pico USBのみでP_MAINのV3D給電が正常とは判断できない。

## 何をしたか

1. USBポート一覧を再取得し、識別済み親機のCOM6を指定した。
2. PlatformIOでWi-Fi対応ファームを確認・書き込み、ツールによるフラッシュ照合と再起動を実施した。
3. USBで`h`を送信して状態を取得し、15秒間の連続応答を保存した。
4. `s`でSD再マウントを1回試み、`h`と10秒間の応答を記録した。フォーマットは行っていない。
