# IMU起動待機の撤廃

| 項目 | 内容 |
|---|---|
| 日時 | 2026-09-21 JST |
| 目的 | 電源投入後の固定待機をなくし、GPSを待たずIMU保存を開始する |
| 対象 | a04537aを基にした本コミットのSony MainCore |
| 判定 | ビルド・書込み成功。起動直後のIMU取得・SD保存を実機確認 |

## 前提条件

Sonyメイン＋拡張ボード、CXD5602PWBIMU（SPI5、960 Hz、4g/500 dps、FIFO閾値1）、前回と同じSDHCIカード、USB給電。COM7のCP210x VID/PIDと個体番号を照合した。Arduino core 3.4.7。親機・子機USBは検出されず、更新対象外。RX、水温、水圧、LCDは対象外。カード型番・電圧実測は未確認。

| 信号 | 既存接続（今回変更なし） |
|---|---|
| PPS自己入力 | Spresense拡張D02→D03、JP1=3.3V（既報ユーザー確認） |
| 親機PPS | D02→100Ω→GP6（物理9） |
| UART | D01 TX→100Ω→親機GP7（物理10）、115200 bps、共通GND |

## 変更・手順

診断版の300秒待機だけでなく、製品ソースに残っていた最大120秒のGPS待機も撤廃した。SDとSubCoreの準備後、IMUタスクはすぐセンサーを初期化する。UTC未成立でも記録し、受信成立後に有効なUTCを付ける既存仕様を維持する。

ファーム書込みのためだけにqで停止し、STOPPED_REMOVE_SDを確認した。MainCoreを書込み、パッケージ検証成功後の再起動から65秒、読取り専用監視を実施。SubCore・共通ログ形式・Pico側コードは変更なし。監視終了時に停止指示は送らない。

## 結果

最初の状態通知で既にIMU 1,408件、SD 1,368行。GNSS更新番号0の時点で取得・保存が始まっていた。最終IMU 63,762件、SD 63,786行、SDエラー0、IMUギャップ0。recording=1で記録を継続。GPS測位・UTCは未成立。

MainCoreビルド、Python8テスト、既存IMU UTC/CRC C++スイート合格。[状態ログ](evidence/status.txt)。生ログはreports/rawへ保存。

## 未検証事項

今回の目的は起動待機の撤廃。GPS受信成功時にSDが止まるとの申告は未解決であり、本変更による修正完了とはしない。GPS/UTC絶対精度、長時間耐久、SD全件読み戻し、物理的な電源再投入は今回未実施。実機確認はファーム更新後の再起動によるもの。
