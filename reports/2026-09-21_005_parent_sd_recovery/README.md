# 親機SDの自動復旧・単独Web操作

- 日時：2026-09-21 JST。
- 前提：ユーザーの先行復旧検証（P_MAIN_experiment/reports/2026-09-21_015_parent_sd_recovery）を確認。再マウントで復旧、2ファイル各172行CRCエラー0、原因未特定。
- 対象：AquaBeacon MAIN親機COM6、USB serial A444A41EE9334705を役割応答と照合。子機は接続・操作・書込みなし。Spresense操作なし。ピン・SPI速度4 MHzは変更なし。親機温度・水圧・磁気センサーとLCDは対象外。
- 環境：Windows / PlatformIO / Arduino-Pico / Zig C++ / Python / Node.js。Wi-Fi変更なし。
- 公開変更元：04d7a1e。画面変更は本レポートと同じコミットに収録。

## 検証

親機ビルドと書込み成功。CRC/通信/時刻の既存テスト合格。SD復旧の待機、3回上限、停止抑止、手動再開、安定30秒後の上限リセット、millis折返しをホストテストで確認。ローカル・Pages JS構文検査と既存スマホ共有テストも合格。

実機の自然発生エラーを確認対象とし、カード抜去や故意の書込破壊による障害注入は実施しない。実機Web操作はユーザー確認待ち。

## 親機SDの復旧（2026-09-21）

先行検証ではWRITE_FAILED後の再マウントで復旧し、時刻・位置ログとヘルスログ各172行のCRC32が一致しました。根本原因は未特定のため、復旧機能は接触・電源・媒体の問題を解消するものではありません。

親機は保存失敗時、5秒、15秒、60秒の待機を挟んで最大3回、自動再認識します。毎回512バイトの新規ファイル読戻しを検証し、新しい番号のログで保存を再開します。旧ログの削除・上書き・フォーマットは行いません。復旧後30秒連続で正常なら試行上限をリセットし、短時間で繰り返す故障では無限に再試行しません。失敗から復旧までの記録は欠落し、後から埋め戻しません。

Webの「親機SDの復旧」で、子機なしでも親機だけの復旧・記録再開と停止ができます。上限到達後も復旧ボタンで再試行可能です。正常保存中の復旧ボタンは新しいファイルを作らず、そのまま継続します。「親機の記録・自動復旧を停止」や従来の記録停止は自動復旧も無効にします。USBのs/qも同様です。安全停止時にSDエラーが出た場合でも自動再開は抑止されますが、保存成功を意味しません。

`sd_recovery`には有効/待機/上限到達、連続試行回数、自動復旧成功累計、最後の失敗理由を表示します。既存のSDエラー累計も保持し、復旧成功で過去のエラーを隠しません。起動時は自動記録・自動復旧が有効になります。今回の改良は親機限定で、子機は接続・書込みしていません。

## 実機結果

110秒の連続保存で35→144行、SDエラー0のまま増加。安全停止後に時刻・位置ログとヘルスログを回収し、各145行のCRC32一致を確認。停止時に自動復旧が無効となり、再開後は両方とも新しいファイル名で11行まで正常保存した。

今回自然発生のSD障害はなく、自動再マウントの実機発動は未確認。回数制限・失敗再試行はホスト模擬テストで検証しており、根本原因の解消や長時間安定性の保証ではない。[公開可能な検証結果](evidence/results.json)。現在親機は記録中、測距は停止。子機は未操作。
