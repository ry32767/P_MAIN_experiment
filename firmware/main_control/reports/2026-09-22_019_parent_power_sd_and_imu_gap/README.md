# 親機外部電源SD・IMU欠落表示の修正

| 項目 | 内容 |
|---|---|
| 実施日時 | 2026-09-22 JST |
| 対象 | P-MAIN COM6 / C-MAIN COM3、外部電源接続状態 |
| 目的 | 外部電源時の親機SD異常を再確認し、親機監視で増え続けるIMU欠落の意味と実データ欠落を切り分ける |
| 判定 | 修正・短時間実機確認合格。数時間の連続確認とSD端子3.3 V波形測定は未実施 |

## 発見したこと

親機は外部電源入力12.53 V付近で、`SYNC_FAILED`、SDエラー12回、自動復旧4回、再試行上限到達を実際に示した。USB通信は生きていたため、USB給電の有無だけではなく、SDの書込み同期時に外部電源系またはSPI信号品質の余裕が不足する間欠故障と判断した。

親機監視の旧`imu_gaps`は、BNO085イベント連番欠落だけでなく、100 Hz固定枠までに姿勢・加速度・角速度の更新が全部そろわなかった枠も加算していた。25秒実測で姿勢2,505件に対し360増加（14.37%）したが、同じ実験で取得済みの全BNOイベントログは4センサとも連番欠落0、CRC不一致0、保存キュー欠落0だった。したがって、旧表示の増加をそのまま実データ消失と解釈するのは誤りだった。

## 修正

- P-MAINのSD SPIを4 MHzから1 MHzへ下げ、C-MAINは4 MHzを維持した。
- SDカード検出、SdFat詳細エラー、実効SPI速度を状態JSONへ追加した既存診断版をP-MAINへ反映した。
- `imu_gaps`をセンサ種別ごとの8 bit BNOイベント連番欠落だけに変更した。100 Hz固定枠の更新有無はCSVの`fresh_mask`、予定枠の飛びは`index`と`scheduled_us`で判定する。
- Web表示名を「IMU欠落・更新不足」から「BNOイベント連番欠落」へ変更した。
- SDが既に`SYNC_FAILED`等で停止している場合でも、安全確認後に書込みできるようフラッシュ手順を修正した。

## 実測結果

| 確認 | 結果 | 判定 |
|---|---:|---|
| 修正前P-MAIN異常 | `SYNC_FAILED`、SDエラー12、復旧4、再試行上限到達 | 異常再現 |
| 修正前の再試験 | 外部電源で110秒、648行、SDエラー0、2ファイル全行CRC一致 | 間欠故障であることを確認 |
| 修正後P-MAIN | 起動125秒、121/122行同期済み、SDエラー0、欠落0、カード検出、SPI 1 MHz | 短時間合格 |
| 修正後P-MAIN電源値 | 12.4975 V、65.625 mA | 外部電源動作を確認 |
| 修正後C-MAIN | 姿勢11,160件、BNO連番欠落0、保存欠落0、SDエラー0 | 合格 |
| 親機が受信した子機状態 | 姿勢11,094件、BNO連番欠落0、リンクエラー0 | 合格 |
| ビルド | parent / child100 成功 | 合格 |
| ホストテスト | protocol / Spresense / phone / SD recovery / UTC / sequence gap 成功 | 合格 |

数値根拠は[evidence/results.json](evidence/results.json)。P-MAINの新規ファイルは`P_MAIN_TIME_POSITION_00017.csv`と`P_MAIN_HEALTH_RANGE_00017.csv`、C-MAINは`C_MAIN_IMU_100Hz_00016.csv`、`C_MAIN_BNO_EVENTS_00016.csv`、`C_MAIN_HEALTH_RANGE_00016.csv`。

## 残る確認

- 1 MHz化後の数時間連続試験は未実施。今回の約2分だけでは間欠故障の根治を断定しない。
- 再発時はP-MAINのSDソケット電源端子または`C_SD2`両端で3.3 Vを測り、同期書込み時の瞬時低下とリップルをオシロスコープで確認する。
- 電源側ではP-PWRの5 V出力とNJU7223F33入力、`C_3S1` 10 µFの容量・極性・実装、P-MAINの`R_SDCS` 10 kΩとSD接点を確認する。
- 固定100 Hzの全行で3種類の新規値が必要な解析では、`(fresh_mask & 7) == 7`の行だけを使う。値の保持行はデータ破損ではないが、新規同時更新でもない。
