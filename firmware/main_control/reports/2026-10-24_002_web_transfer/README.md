# 親機Web読み込み停止の調査・修正

## 前提

2026-10-24、ユーザーはスマホで http://192.168.4.1 を開くと読み込みが遅く何も表示されないと申告。親機メインとSpresense接続、送信基板には何も接続していない。PC Wi-Fiは切替禁止。親機温度/水圧/LCDは対象外。

## 実施

- USB状態照会で親機の状態更新・SD記録・Spresense通信継続を確認。
- 公開GitHub PagesをHTTP GETで取得。HTTP200、29682byte、Last-Modified=2026-09-21 02:55:58 GMT。現在の内蔵画面55456byteとは異なり、tab-status/api/spresense/calibrationなし。公開ページは今回更新していない。元リポジトリは変更していない。
- スマホが開いているのは親機IP直結と確認したため、公開ページの古さは今回の読み込み停止の直接原因としない。
- web_control.hには接続開始から7秒の一律切断があり、大きなHTMLを低速送信している途中でも切ることを確認。実際のスマホ通信を観測していないため、今回の症状の原因と断定しない。
- 7秒の無進捗期限と120秒の全体期限へ変更。実送信/受信バイトで進捗時刻を更新。TCP_NODELAY、送信上限1460byte。部分書込みの残りを保持。
- README/docs/spec.mdを更新。実際のwebTick送信経路をモックTCPへ接続する回帰試験を追加。ホスト試験へ組込み。
- 親機USBシリアル番号A444A41EE9334705・role=P_MAINを再確認。flash.pyでSD記録停止後、parentだけ書込み。Spresense/子機の書込み、送信開始、既存ログ削除/フォーマット、PC Wi-Fi切替は実施していない。

## 実測・検証

- 7秒超の55456byte完送、部分送信、ゼロ書込み時の失効、7秒無進捗期限、120秒全体期限、millis周回の回帰試験成功。

- 更新後role=P_MAIN、測距送信停止。親機SDはsd_reason=NONE、新規P_MAIN_TIME_POSITION_00014.binへ記録。保存行7→14、最終同期済み14。
- Spresense通信fresh、imu_ok=true、CRC/framing/overflow/collision各0。Spresense SD未認識・記録停止は継続。

## 追跡調査：到達不能（2026-10-24）

ユーザーから修正版でも「このサイトにアクセスできません」と申告。スマホのWi-FiはAquaBeacon-MAIN接続済み、192.168.4.xxxとの回答。USBで親機稼働、SD記録・Spresense通信継続を確認。先の転送期限修正で症状が解消したとは扱わない。

親機USB Wに読取り専用のAP/HTTP診断を追加。HTTP GET /api/pingに小さなJSON応答を追加。要求本文・パス・端末識別子・認証情報は診断へ出力しない。既存ピン設定/Spresenseの受信設定は変更なし。ホスト試験・親機ビルド成功。USBシリアル番号とroleを再確認し、記録停止後に親機だけ更新した。

更新後のUSB実測：AP起動成功、mode=2、AP IP=192.168.4.1、接続1台、TCP待受=true、受付/要求/送受信バイト/期限切れ各0。接続した端末の識別は行っていない。ユーザーへスマホからhttp://192.168.4.1/api/ping再試行を依頼し、USB診断で到達有無を監視。これは監視開始時の値であり、ユーザーの再試行中も要求0とはまだ断定しない。

## 追跡調査：ping成功・トップ画面停止

ユーザーが/api/pingでok=trueを確認。その時点でUSB診断のTCP受付/要求が4件、返信計276byte、完送2件となり、小さなHTTP応答の到達を確認。同じスマホでトップ画面を開くと読み込み継続との回答。監視中は受付7→8、要求7→8、最後の返信コード200だがresponse_bytes=0/response_sent=0、送信量276byteのまま、期限切れ3→5。トップ画面の返却データ生成が空になることを観測。大きなString一括構築時のメモリ確保失敗が疑われる。最大連続確保可能量・malloc失敗自体は未測定。

トップ画面をString(WEB_PAGE)へ変換せず、フラッシュ内静的HTMLと小さいHTTPヘッダーを分離して送る方式へ変更。Content-Lengthは静的本文のUTF-8バイト数。部分送信時のヘッダー/本文境界、1byte・137byte・1460byteずつの送信内容完全一致を模擬検証。既存の無進捗/全体期限、時計周回試験も成功。ホスト試験、parent/child100ビルド成功。親機だけ安全停止・識別後に更新。スマホ再確認は更新完了後に実施予定。
