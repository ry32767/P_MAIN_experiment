## 調査結果：実装はテザー基準の片道ToF測距

親機のアラーム処理でRS485開始マーカー0x00とPIO音響送信を起動する。子機はCRC付きSCHEDULEで待機を準備し、GP1のテザー受信開始エッジを割込み捕捉、マーカーバイト確認後に基準として採用する。GP2音響比較器で受信候補を捕捉する。

```text
差分時刻 Δt = 子機の音響エッジ時刻 − 子機のテザー受信開始時刻
表示距離[m] = Δt[µs] × 1500[m/s] / 1000000
```

両時刻が子機の単調時計なので、親子時計の絶対差・スマホ時刻・GNSS UTC・カメラ同期を距離計算に使わない。音響の往復応答ではないため2で割らない。親子の相対同期とUTC共有は他の時刻対応のために残る。

根拠：src/main.cppのfireShot、onTetherEdge、子機SCHEDULE/RESULT処理、statusJson、common/ranging.h、common/protocol.h、common/acquisition.h。

## 信号と検出
- 選択周波数10/50/100/200kHz、各バースト5波。現在の起動既定値はsrc/main.cppのacquisitionConfigで200kHz・1回/秒・可変3連モード。汎用AcquisitionConfig型の既定pattern=0と混同しない。
- 単発は条件を満たした比較器パルスの先頭、3連は事前通知された2つの間隔が合う3パルスの先頭を採用する。パルス幅は6µs以上、3連では600µs以下も条件にする。搬送波位相推定やチャープの相関処理ではない。
- 3連の休止間隔は1.0〜5.2msと7.0〜11.2msの各8段階で64通り。IDと間隔をテザーで通知し、RESULTも予約と照合する。間隔許容は±200µs。同じIDは同一起動中に16秒以上空ける。
- 前の送信と異なるパターンを使うことで誤採用低減を狙う設計だが、同じ送信からの反射も同じパターンを持つ。直達音を受けられない場合、反射を距離として採用する可能性が残る。混合・重畳反射の全条件を排除する保証はない。
- 受信窓は基準から22ms、3連の確認に末尾時間を追加。負ToF・基準なし・窓外・候補/エッジ溢れは正常距離にしない。200µs未満は近接・未校正として参考表示する。
- 観測枠は包絡線ADCを20kSa/sで記録し、受信後1〜5秒の反射調査に使用する。現在の既定は3秒・30枠に1回で、観測時は後続送信を休止する。200kHz搬送波そのものの波形保存ではない。

## 現在得られるのは距離で、位置・方位は未推定

単一の距離は3次元では親機を中心とする球面の制約に相当する。深さが分かっても通常は円周上の候補が残り、単一の距離と機体IMUの姿勢だけでは音の到来方向や一意の子機座標にならない。現行コードに受信アレイの方位推定や、この観測から子機の3次元座標を解く推定処理は確認できない。

| 方式 | 使用する観測 | 現行との違い |
|---|---|---|
| 現行のテザー基準片道測距 | 子機内の電気基準→音響到着の差 | 得られるのは親子の距離1本 |
| USBL | 音響距離と受信アレイによる角度 | 到来方向を測れる受信系・取付/姿勢補正が必要 |
| LBL | 既知位置の複数基準点への距離 | 複数の基準点と幾何配置・音速補正が必要 |

USBLは距離と角度を組み合わせる方式、LBLは既知位置の複数音響基準への距離から位置を求める方式である。一次資料：[Sonardyne USBL](https://www.sonardyne.com/products-knowledge-base/what-is-a-usbl-and-how-does-it-work/)、[Sonardyne LBL](https://www.sonardyne.com/products-knowledge-base/what-is-lbl-long-baseline-underwater-positioning/)。これら市販方式の距離・精度仕様を本機へ転用しない。

## 精度を制限するものと確認順
1. **電気・音響の遅延校正。** 同一コールバック内のUART/PIO起動は物理的同時性の保証ではない。RS485変換・ケーブル伝搬・割込み・TX/RX回路・比較器しきい値による検出遅延が差分へ入る。複数の既知距離で、Δt=r/c+bという一次モデルの傾き/切片と残差を調べる。信号強度で遅延が変わる場合は固定bだけで補正できない。
2. **音速。** 現行は1500m/s固定で、温度・塩分・深さによる補正なし。水中音速は条件で変わるため現場条件に合わせた確認が必要。[NOAAの音速計測説明](https://nauticalcharts.noaa.gov/learn/hydrographic-survey-equipment.html)。
3. **反射・回り込み。** 既知距離、振動子の向き、直達経路の有無、送信停止時を分けて受信成功率/誤採用/包絡線を比較する。近接のエッジだけで音響伝搬を証明しない。
4. **座標への拡張。** 目的が子機の位置なら、複数距離・到来方向・画像による移動推定など、追加の独立した観測と推定処理が必要。カメラ/IMU/深度/距離の融合は将来案であり、今回未実装。

1500m/sの仮定下で、22msは33m相当の計算窓、100µsの遅延誤差は0.15m相当。これらはPythonで計算したモデル例で、本機の到達距離や誤差の測定値ではない。1µs=1.5mm相当も数値換算であり測距精度ではない。±200µsのパターン照合許容を距離精度保証へ読み替えない。計算はraw/acoustic_model.jsonへ保存。
