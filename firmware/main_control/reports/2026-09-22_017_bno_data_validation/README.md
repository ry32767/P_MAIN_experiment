# BNO085データ実値検証

| 項目 | 内容 |
|---|---|
| 実施日時 | 2026-09-22 JST |
| 目的 | SDへ保存されたBNO085値が固定値の複製ではなく、センサーイベントとして妥当か確認する |
| 対象 | C_MAIN / BNO085、前レポート016で回収した100 Hzログ101.94秒 |
| 判定 | 合格。固定値ではなく、姿勢・加速度・角速度・磁気の実変化を確認。軸方向の既知角度試験は未実施 |

## 前提条件

解析対象は`reports/raw/2026-09-22_016_child_sd_recovery/imu.csv`と`events.csv`。いずれも全行CRC一致、ゼロ埋め0、BNOイベント連番欠落0を確認済み。今回の解析では実機、親機COM6、子機COM3を操作していない。

定周期IMU CSVは100 Hzの時刻格子に最新値を保持する形式であり、BNOイベントが次の格子まで来なければ前値を保持する。`fresh_mask`のbit0/1/2/3が、それぞれ姿勢/加速度/角速度/磁気の新規更新を表す。全BNOイベントCSVはsensor_id 8/1/2/3をそれぞれ姿勢/加速度/角速度/磁気として保存する。

## 何をしたか

1. 定周期IMU 13値の完全一致行、ユニークベクトル数、各列の最小・最大を集計した。
2. 四元数ノルムを計算し、単位四元数として妥当か確認した。
3. 加速度・角速度・磁気の3軸ノルムを計算した。
4. 最初と最後の有効四元数から姿勢差を計算し、角速度ピークとともに動作応答を確認した。
5. ローカルのAdafruit BNO08xデコーダと保存コードを照合し、Q14姿勢、Q8加速度、Q9角速度、Q4磁気が対応する構造体フィールドからCSVへ渡されていることを確認した。

## 結果

| 確認項目 | 実測 | 判定 |
|---|---:|---|
| 定周期行数 | 10,195行 | 対象成立 |
| 異なる13値ベクトル | 9,260種類 | 固定値ではない |
| 直前行と13値すべて同じ | 478組、4.689% | 前値保持として妥当 |
| 有効四元数ノルム | 中央値1.000001、最小0.999958、最大1.000043 | 単位四元数として妥当 |
| 姿勢変化 | 最初から最後まで126.186° | 回転応答あり |
| 加速度ノルム | 中央値9.899 m/s²、範囲3.565–16.598 m/s² | 重力と移動応答あり |
| 角速度ノルム | 最大3.980 rad/s | 回転応答あり |
| 磁気ノルム | 中央値37.230 µT | 実値あり。ただし最大346.934 µTで周辺磁性体の影響または未校正の可能性 |
| 新規更新行 | 姿勢9,698、加速度9,710、角速度9,717、磁気2,553 | 設定レート差と整合 |
| 全BNOイベント | 加速度12,722、角速度10,209、姿勢10,208、磁気2,553行 | 4種取得済み |

![BNO085値の妥当性](figures/bno-validity.svg)

数値根拠は[evidence/results.json](evidence/results.json)。四元数ノルム、重力加速度付近の中央値、角速度ピーク、126°の姿勢変化が同時に成立しているため、SD処理が同一レコードを複製している状態ではない。

同じ数値が連続して見える主因は、100 Hz固定格子が「最新値保持」であることと、BNO出力の量子化である。特に磁気は実測約25 Hzのため、100 Hz CSVでは概ね4行に1回だけ更新される。解析では値だけでなく`fresh_mask`を使用し、全センサーが新規の行だけが必要なら`(fresh_mask & 7) == 7`、姿勢だけなら`fresh_mask & 1`で抽出する。

## 未検証事項・次の確認

- 今回の記録中に実機が動いたことは数値から確認できるが、「基板をX軸正方向へ既知の90°だけ回した」などの統制された操作ではない。軸符号、取り付け方向、既知角度に対する絶対精度は未検証。
- 磁気は周辺の鉄・磁石・電流配線の影響を受ける。今回の最大値は地磁気のみとしては大きく、校正合格とはしない。
- BNO内部`source_us`の微小逆転1件は前レポート同様に残る。CRC・連番・ホスト取得時刻の破損ではないが、精密な時間解析では検出して除外する。
