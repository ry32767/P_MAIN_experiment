# 子機BNO085ログのSD保存・自動復旧

| 項目 | 内容 |
|---|---|
| 実施日時 | 2026-09-22 JST |
| 目的 | C_MAINのBNO085データがSDへ正しく保存されることを再検証し、SD障害後に保存が永久停止する問題を修正する |
| 対象 | C_MAIN / Pico 2 W、C-MAIN v4.5、100 Hz構成。ローカル作業スナップショット（Git管理情報なし） |
| 判定 | 一部合格。正常時の保存・読戻しと復旧制御の実装は合格。実カード障害からの自動復旧発動は未注入。BNOセンサー時刻の微小逆転は未解決 |

## 前提条件

子機COM3（USB serial `A521D21EB1DCFB44`）をUSB個体番号と`role=C_MAIN`応答で照合した。親機COM6（`A444A41EE9334705`）も接続中だが、作業中のためシリアル操作・停止・書込み・SDファイル回収を行っていない。子機にはBNO085、microSD、C-PWRと低速I2Cセンサーが接続され、外部給電時のバス電圧は状態値で約11.69 V、再起動直後はUSB給電相当の約4.66 Vだった。カードの型番・容量、給電波形、接点状態は未確認。

ピン変更はない。BNO085はSPI0（MISO GP16、CS GP17、SCK GP18、MOSI GP19、INT GP20、RESET GP21）、SDはSPI1（SCK GP10、MOSI GP11、MISO GP12、CS GP13、CD GP15）の既存割当を使用した。BNO SPIはライブラリ既定1 MHz、SDは4 MHz。

## 何をしたか

1. 修正前の子機を停止せず約12秒観測し、定周期ログ・全BNOイベント・同期済み行・SDエラー・欠落の推移を確認した。
2. コードを確認し、親機にはSD失敗後の有界自動復旧がある一方、子機は一度失敗するとBNO取得だけ継続して保存が永久停止する差を特定した。
3. 子機限定で、5秒・15秒・60秒の最大3回再マウント、30秒正常後の試行数リセット、安全停止時の復旧抑止、手動再開、状態JSONを追加した。既存ファイルは削除・上書きしない。
4. ホスト試験、子機50/100 Hzと親機の3構成をビルドした。USB個体と役割を再照合し、稼働中の子機ログだけを`q`で同期・クローズして子機100 Hzへ書き込んだ。
5. 約102秒保存後、子機だけを安全停止し、IMU・全BNOイベント・ヘルスの3ファイルをUSBで全量読戻しした。全行CRC、ゼロ埋め、100 Hz格子、BNOイベント連番を検査した。
6. 新しいログで記録を再開し、子機が保存中へ戻ったことを確認した。

## 未検証事項・次の確認

- 今回は正常なカードを意図的に抜去・短絡・電源断していないため、実機で`waiting`→再マウント→`recoveries`増加となる障害注入試験は未実施。復旧は接点・電源・媒体の根本原因を直すものではなく、復旧までのデータは欠落する。
- 過去に確認された先頭ゼロ化やCRC破損は今回の新規3ファイルでは再発しなかった。安全停止前のカード取り外しや電源断に対する完全な保全は保証しない。
- BNO085の`source_us`微小逆転はSD書込み破損とは独立した既知課題。厳密なセンサー時刻解析では`acquired_us`との併記と逆転検出を継続する。
- RTCは2000年で無効、親子リンクは今回の子機単独観測中に未接続だった。UTC精度・測距・センサー絶対精度は本試験の対象外。
