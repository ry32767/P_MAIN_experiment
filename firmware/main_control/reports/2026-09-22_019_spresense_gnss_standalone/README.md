# Spresense GNSS単体受信確認

| 項目 | 内容 |
|---|---|
| 実施日 | 2026-09-22 JST |
| 目的 | 統合ファームを修正する前に、既存のSony公式GNSS単体スケッチでGPS受信を確認する |
| 対象 | Sony Spresense、COM7、Arduino core 3.4.7 |
| 判定 | GNSS更新と衛星信号検出は確認したが、UTC取得・位置Fixは未成立。統合版の修正は未実施 |

## 前提と使用物

隣接する`spresense-gps-validation/gnss_validation/gnss_validation.ino`を使用した。Sony公式GNSSサンプルを基に、GPS + GLONASS + QZSS L1C/A、cold start、1秒更新、115200 bpsに設定されている。接続先はCP210xのCOM7（USB個体番号`10878C89E6DBED1197F5F12D62C613AC`）。アンテナ位置、空の見通し、給電電圧は今回実測していない。

書込み前の統合版はIMU・SD記録中で、GNSS状態は`visible=0`、`satellites=0`、`utc_s=0`だった。単体版への書込み前にSD停止命令を送っていないため、直前の統合版ログ`I00028.CSV` / `G00028.CSV`の末尾は正常終了していない可能性がある。既存ログの削除・SDフォーマットは行っていない。

## 実施内容

1. 単体スケッチを再ビルドし、COM7へ書き込んだ。
2. ボード側の`Package validation is OK.`と再起動を確認した。
3. シリアルを開き直すとボードが再起動するため、最終判定はポートを開いたまま330秒連続で観測した。
4. 緯度・経度を含み得る生ログは`reports/raw/`のみに保存し、公開レポートでは件数だけを扱った。

## 結論と次の確認

ユーザー指定の「GPS単体検証が動いたら修正」の条件を満たさないため、統合ファームのソース変更・再書込みは行っていない。Spresenseには現在、単体検証スケッチが書き込まれている。

アンテナ面を上にして空が広く見える場所へ移した後、同じ単体版を再起動せずに監視し、現在日時への遷移と`Fix`を確認する。その時点で単体版が成立した場合に限り、統合版のIMU開始順序などとの差分を修正・再検証する。
