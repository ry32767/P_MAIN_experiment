# Spresense SD書込みタイムアウトの原因切り分け・再発防止

## 前提

- 2026-10-24 JST。前の検証ではSD書込み中のerrno=110（ETIMEDOUT）を繰り返し、自動復旧後も再発していた。
- ユーザーが別チャットでRTK-GNSS作業を行うため、この検証では**親機COM6に接続せず、親機の書込み・再起動・GNSS設定を行わない**。変更はSpresense用ソース、共通の新規書込み境界ヘルパー、Spresenseビルドスクリプト、試験・資料に限定。子機は未接続・未操作。
- Spresense COM7 / USBシリアル10878C89E6DBED1197F5F12D62C613ACを照合し、通常ロガーのIMU_LOG / FORMATTER応答と停止完了を確認してから診断版を書込み。診断版は独自応答とアイドル状態を確認。SDKはSony Arduino 3.4.7。SubCore1 formatterの形式は変更せず、MainCoreだけ書き換える。
- 既存のピン割当を維持。診断中D03は入力のみで、PPS出力・GNSS動作は行わない。親機温度・水圧・LCD、音響動作、時刻・距離・IMU精度は対象外。
- カードメーカー・型番・公称容量、給電方法と波形は未回答／未実測。カード・配線の差し直しは行わない。PC Wi-Fi切替、フォーマット、既存ログ削除は行わない。新規診断ファイルDxxxxx.BINも保持する。

## 原因の判定

**今回の実機・SDK構成での再現条件は、CXD5602PWBIMU取得中に512byteを超える書込みを発行すること。** IMUなしでは6000byte書込みも成功し、IMUありでは1024byteと6000byteでerrno=110が再現。通信タイマーなしでも再現した。512byte書込みはIMU・タイマー併用でも成功した。

4096byte要求は今回の1回では成功したため、「すべての複数セクタ書込みが必ず失敗する」とは判定しない。一方、512byte以内に境界をそろえて分割した6000byte要求は、再現した負荷条件のまま3回連続で4MiBを完走し、読戻しが一致した。記録処理の書込み方式とIMU同時動作の相互作用を実測で絞り込んだ。

カード不良、容量不足、フォーマット不一致、通信タイマー単独を今回の原因として断定しない。BPB読取りでFAT32、空き容量ありを確認。SDKの複数ブロック経路とIMUのDMA・割込み・電気的要因のどれが最下層の発生機序かは、ドライバー内部トレース・波形・別媒体／別個体比較をしていないため未確定。SDK自体の不具合と断定するものではない。

## 実施した対策

- `common/sd_sector_write.h` のwriteLimitで1回の書込みを最大512byteに制限し、現在のファイル位置から次の512byte境界を越えないようにする。CSVヘッダーや参考UTC行で位置がずれていても対応する。
- 通常ロガーのwriteCompleteは現在位置を取得し、残りを順に書き込む。短い正の書込みでは実際に進んだ分だけ位置を進め、EINTRは再試行、その他の失敗は従来のSD障害処理へ渡す。単にタイムアウトを無視したり同じデータを無条件に再送したりしない。
- CSV列・桁数・CRC、960Hz取得設定、校正値、通信フレーム、ログファイル名・既存ログは維持。以前の2バッファ処理と安全停止・自動復旧も維持。
- ホスト試験に全512種類の開始位置、各種長さ、短い書込み後の再開位置、4GiB境界を超えるヘルパー計算を追加。
- 単独診断用sketchをfirmware/spresense/sd_diagnosticへ追加。新規ファイル排他作成、サイズ・所要時間・errno・同期・読戻し一致を記録する。通常ビルドには自動で組み込まない。

## 通常ロガーの確認

300秒のUSB連続観測で293件の状態を取得。取得サンプル0→285757、SD保存行数（参考UTC・ヘッダー等を含む）2→285814。SDエラー、IMUエラー、IMU欠落検出、IMUキュー廃棄、参考UTCキュー廃棄はいずれも0。取得／保存カウンターの逆転・リセットや保存停止なし。最初から最後の状態までの観測幅は295.734秒（300秒の窓には初期化待ちを含む）。

300秒観測とは別に、USBを開き直したセッションで新規ファイルへ短い実IMU記録を作成し、安全停止してUSB回収。実CSV 2035データ行（連番201〜2235）について、CRC不一致0・連番欠落0・非有限値0・無補正時の生/補正値一致を確認した。5分ログ全量を回収したという判定ではない。回収後は新規ファイルで通常記録を再開し、最終10秒観測でもrecording=1 / sd=1、SDエラー・IMUエラー・欠落検出・キュー廃棄0を確認した。

## SDKソース確認

インストール済みconfigではSDIO DMAとIMU SPI5 DMAが有効。公式SDK v3.4.7のnuttx submoduleはa98b7ce090a0db5aa36c0feced496592735c5c57。ソースでは単一ブロック書込み（CMD24）と複数ブロック書込み（CMD25）が別の処理経路となる。これは対策の背景であり、内部のどの待機がタイムアウトしたかを直接捕捉したものではない。

## ビルド・試験・制限

- Spresense formatter / loggerビルド成功。今回のloggerは306288byte。MainCore書込み済み。formatterは内容・共有構造を変えておらず、再書込みしない。
- 指定venvでscripts/test_host.py成功。書込み境界の追加試験と既存の校正・CSV・CRC・通信試験を含む。
- 診断試験は単独環境とIMU同時環境を分け、診断終了後は通常ロガーへ復帰。親機のビルド／書込み・GNSS設定は実施していない。
- 今回確認した条件・時間を超える長期保存、別のSDカード／ボード、電源断耐性、温度変化、実機Web、絶対精度は未検証。5分成功を永久的な無故障保証とはしない。
