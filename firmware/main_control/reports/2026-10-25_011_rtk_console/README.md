# RTKコンソール：検索・選択の安定化・前回受信局

## 前提
- Pico 2 W / Arduino-Pico / PlatformIO。現行フォルダー内のみ変更し、元リポジトリ・ピン・配線は変更しない。
- PCのWi-Fi切替、実機書込み・実機Web操作、SDフォーマット・ログ削除は行わない。
- 前回局は「CRC検証済みRTCMをGNSS送信キューへ投入できた局」。TCP応答やFIX判定とは区別する。

## 実施
- 5秒ごとの選択欄再生成を廃止し、サーバー・ポート・一覧世代ごとに一度だけ取得。検索時はローカル絞込み。遅れて届いた旧サーバーの応答を破棄。
- 局名・配信先名・衛星・ネットワークの部分一致検索。全角英数を正規化し複数語AND検索。0件でも入力済み配信先は保持する。
- 局名（説明）と配信先名（接続ID）を併記し、選択と入力を同期。選択局詳細と親機が使用中の接続先は別表示。
- 公称配信情報・GGA要否・親機GNSSとの概算距離を表示。位置の更新途絶時は測位待ち。
- GPS MSM4〜7の信号マスクと有効セルからL1/L5信号情報の受信を表示。TCP接続ごとにリセットし、15秒更新途絶・停止時は未確認とする。搬送波有効性・補正採用は判定しない。
- 前回受信成功時の接続設定を専用CRC付き二重スロットAQ_LAST_A.cfg / AQ_LAST_B.cfgへ保存。通常の設定保存と独立し、同一内容を再書込みしない。SD異常・転送・停止処理・制御処理中は保留し、失敗時は30秒間隔で再試行。
- 前回局への再接続API・ボタン。保存時のサーバー・配信先・認証・テザリング設定を復元する。起動時に履歴を読んでも通常設定を勝手に置き換えない。
- README・docs/spec.md・web/DESIGN.mdを同期。docsの増減なし。

## 制限・未検証
- 検索は既存と同じ先頭64対応局。上限と全件数を明示し、未掲載局は直接入力。最寄り自動選択は全取得対応局が対象。全局検索・ページングは未実装。
- 公称情報は固定長保持で、非常に長い説明等は切り詰められる。2周波表記のみでL5対応とは判定しない。
- 実機SDの自動保存・再起動保持・再接続、全64局時の動的メモリ余裕、SD同期の記録遅延・欠落への影響、スマホ実機の選択ポップアップ操作は未検証。
- SD保存は親機メインループで実施する。正常記録中にも小さい設定レコードを書込み・同期するため完了待ちの遅延があり得る。
- 実基準局の信号情報、GNSS補正採用、RTK FIX、時刻・位置・距離精度は未測定。いずれも合格とは扱わない。
- 接続情報は従来同様SDに暗号化せず保存する。パスワード・ユーザー名をAPI応答に含めず、CFGファイルはログ回収対象外。
- 画像は模擬データであり、実局の距離・配信状況ではない。

## 実機で次に確認する手順
1. USBシリアル番号と応答で親機を識別してから更新。PCのWi-Fiを変えずWeb操作はユーザーがスマホで行う。
2. 一覧を検索・選択し、定期更新中にも選択ポップアップが戻されないか確認。
3. 補正件数が増え「前回受信成功局をSDへ保存・読戻し確認済み」になるか確認。
4. 再起動後、前回局の表示と再接続で同じサーバー・配信先へ戻るか確認。
5. 別局への接続失敗で履歴が変わらないこと、未測位時は距離が測位待ち、L5未確認が非対応扱いにならないことを確認。
