# 親機・子機 統合ファームウェア検証

実施日: 2026-09-20 JST。新規フォルダ `AquaBeacon_MAIN_firmware`。**本番候補コードの作成・センサ/保存/テザー/Webの検証は進んだが、音響測距は未成立。現在は送信停止。**

## 前提

ユーザー申告: 親子USB、RS485テザー、TX/RX基板と振動子は接続・給電済み。十数cmの容器に水を入れ、振動子間は数cm。Spresenseは電源OFF。親機温度・水圧センサとLCDは未接続のため検証対象外。

USB個体と旧ファームの応答を照合して書込み対象を決定した。

|対象|USB|個体シリアル|
|---|---|---|
|親機|COM6|A444A41EE9334705|
|子機|COM3|A521D21EB1DCFB44|

Pico 2 W / PlatformIO / Arduino-Pico。ピンはAquaBeaconの基板生成スクリプトと実配線資料を参照。Spresense用GP6/7は入力で、旧GP7出力コードを流用していない。既存リポジトリは変更せず、ビルド環境のみ共用した。基板資料の[SHA-256](evidence/source_hashes.json)と、新規コードの[マニフェスト](evidence/firmware_manifest.json)を保存。新規フォルダにはGit commitを作成していない。

## 作成した機能

- 親機/子機の役割別ビルド、子機50 Hz / 100 Hz構成。現在実機は子機100 Hz。
- RS485のCRC32付き双方向通信、4時刻による親機単調時刻への同期、通信断の失効判定。
- PIOの有限長200 kHz・5波送信、1秒周期の測距シーケンス。起動時停止、`T`開始、`X`停止。
- 子機BNOの固定グリッド保存＋全イベント保存。SD/I2C/Webと取得処理を別コアへ分離。
- SD新規ファイルの読戻し検証、CRC付きログ、1秒ごとの同期、キューを空にしてから保存停止、USBログ回収。
- 子機水温/水圧/電源/BNO、親機電源などの取得。漏水のLOW継続判定、比較器HIGH/LOWとエッジ数。
- 親機Webに両機のSD・センサ・通信・測距状態を表示。通信途絶時に古い正常表示を残さない。

### BNO実レート

100 Hzの固定保存とは別に、全イベントログから算出した。

|センサ|イベント数|実レート|連番欠落|
|---|---:|---:|---:|
|姿勢（Game rotation vector）|12,575|100.21 Hz|0|
|角速度|12,575|100.21 Hz|0|
|加速度|15,818|125.97 Hz|0|
|地磁気|3,145|25.05 Hz|0|

加速度と地磁気は要求周期と内部の実レートが異なる。固定100 Hzログで全3種がその枠に新規更新された行は11,072/12,557行。これは固定グリッドと各レポートの位相差・まとめ受信の影響を含むため、**固定行数だけで全センサの実サンプル数を数えない**。全イベントログにはその分も保持し、連番欠落0を別途確認した。

## 修正・切分けの経過

1. 親機旧ファームはSD MOUNT_FAILEDだったが、新コードでは両機の新規読戻しに成功。旧不具合の原因が確定したわけではない。
2. BNOのSPI HALを即時復帰にする初期変更は取得不良となったため撤回。初期化の待ち時間を維持し、INT LOW時だけ通常ポーリングする方式へ変更。SH-2コールバックで同じパケット内の全センサイベントを処理する。
3. Adafruit BNO08x 1.2.5のSPI読出し時刻基準が未設定だった箇所へ `micros()` を設定。イベント時刻をゼロ基準のまま扱わない。
4. 全イベントを1 MHz SDへ追加保存するとキュー溢れが発生。4 MHzへ変更後、同時保存で溢れ0となった。
5. 高速USB読戻しをPC側で1バイトずつ行う行読出しでは欠落が発生。デバイス側の短書込み処理とPC側のブロック受信を整備し、**同一SDファイルの再取得で全行CRC一致**を確認。SD内容の破損とは区別した。

## 残る確認

- 親機の実給電方法と磁気センサ接続。
- RXの6芯ケーブルの両端ピン対応。設計順は1=3.3V、2=GND、3=しきい値、4=包絡線、5=未使用、6=比較器出力。実測包絡線値が設計想定と合わないため、しきい値を上げる試行はしていない。
- RX入力が正常化した後、送信波形確認・音響受信・既知距離での遅延校正と距離精度試験。現在の数cm配置では200µsの早期反応区間（音速1500 m/sで0.3m相当）内になる。
- 漏水刺激、通信断/復帰、SD満杯/抜去/電源断、長時間耐久。RTCバックアップとUTC精度は未検証。
