# 子機SD停止・再開と親機ヘルス反映

実施日: 2026-09-20 JST。既存の統合ファームを再書込みせず、USBで子機記録の停止・再開を試験した。

## 前提

親機COM6/A444A41EE9334705、子機COM3/A521D21EB1DCFB44を再照合。両機SD保存中、子機100 Hz、測距送信停止。Spresense OFF、親機温度/水圧/LCDの除外条件は前レポートと同じ。物理配線の変更はしていない。

## 方法・結果

1. 子機に `q` を送り、キュー排出とファイル同期後のSTOPPEDを確認。
2. 子機のSD正常フラグが落ち、親機のremoteにも同じ停止状態が伝わることを確認。親機自身のSD正常フラグは維持。
3. 子機の記録行数と同期済み行数が28,234行で一致。
4. `s` で再開し、C00010.CSVからC00011.CSVへ新規ファイルを切替。全BNOイベントファイルも新規名へ切替。
5. 子機と親機remoteのSD正常フラグが復帰し、親機remoteで新ログ352行を確認。子機SDエラーの増加なし。
6. 最後まで親機の測距送信は停止状態。

**判定: PASS（SD停止/再開とテザー経由のヘルス反映）**。ブラウザ画面を同時観測した試験ではなく、親機のWeb状態生成にも使うUSB状態JSONを確認した。

根拠: [状態遷移](evidence/lifecycle.json)、[連続観測](evidence/observations.jsonl)。再実行手順は `python scripts/test_sd_health_lifecycle.py`。これは子機の記録を一時停止する実機試験であり、連続計測本番中には実行しない。
