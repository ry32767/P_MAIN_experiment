# SD容量と記録可能時間の試算

## 前提・実施

2026-10-25 JST。容量見積りの依頼に対し、現行ソース、過去の実記録、Sony SDK設定を読取り、Pythonで計算。親機・Spresense USB、GNSS設定、Wi-Fi、SDカードにはアクセスせず、ファームも変更していない。既存ログの削除・フォーマットなし。RTK-GNSSチャットは直近の説明のみ参照し、記録周期等の変更が確定しているとは扱わない。

空カードの公称容量を1GB=10^9byteとして計算。ファイルシステムの管理領域・既存ログの分は実際の空き容量から引く。数値は容量消費の目安であり、無欠落の連続記録や長時間安定性の合格判定ではない。

## Spresense

現行は960Hz、CSVで温度・生6軸・補正6軸・時刻・連番・校正番号・CRCを記録。前日の実CSV2035行から平均178.397byte/行、実測約172348byte/s=約0.62045GB/時。桁数・符号・値・参考UTCログで増減するため、容量表は0.62〜0.70GB/時で試算。

前日のstatfsで認識された記録領域は532676608byte。空でも約45.7〜51.5分相当で、既存ログと診断ファイルがある現状の残時間とは異なる。公称カード容量や実際の最新空き領域は今回未確認。

## 親機

現行コードは通常の時刻・位置58byte/秒＋ヘルス236byte/秒に、GNSS UBX、RTCM、5秒周期JSONメタデータ、測距時の追加イベントを保存する。子機の高周波包絡線・全IMUログは子機SDへ保存し、親機SDへ同じ全量を複製していない。

2026-10-10のPPK実測からUBX約756.61byte/s、メタ約223.90byte/s、固定294byte/s、合計約4.588MB/時。この記録はRAWX約1Hz・RTCM=0であり、現在のRTK補正受信中の実測値ではない。表は丸めた5MB/時を例にし、衛星数・信号数・取得周期・RTCM量で増減する。消費が10MB/時なら表の親機時間は半分になる。真の最大時間を固定値で保証しない。

## 連続記録の制限

容量だけの表を、そのまま現行ファームの連続無欠落記録時間としない。

FAT32の1ファイルは約4GiBが上限。[Microsoftの仕様比較](https://learn.microsoft.com/en-us/windows/win32/fileio/filesystem-functionality-comparison)。加えて今回のSony Arduino 3.4.7 SDKはCONFIG_FS_LARGEFILE未定義で、sys/types.hのoff_tは符号付き32bit。現行writeCompleteはlseekで現在位置を得るため、約2GiB（2147483647byte）を超える1ファイルは安全に扱えると判断できない。Spresenseでは約3.07〜3.46時間でこの境界に届く計算。これは設定・コードの静的確認で、2GiBを実際に作る境界試験は未実施。

現行のファイル切替は起動・記録再開・障害からの復旧時。サイズ到達前の計画的な自動分割は無い。上限を踏むと書込み障害→復旧処理へ進む可能性があるが、欠落のない連続記録として保証できない。大容量を長時間連続で使うには、上限に達する前のファイル分割が必要。

SonyのArduinoガイドの対応容量案内は32GBまで。[Sony公式案内](https://developer.spresense.sony-semicon.com/development-guides/index?lang=en&page=arduino_developer_guide)。64/128GBの行は容量計算のみで、Spresenseでの認識・書込み対応を確認した値ではない。
