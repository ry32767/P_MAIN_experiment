# 親機センサフュージョンに向けた時刻同期・校正の監査

## 前提

- 2026-10-25 JST。親機内装CADは今回未提供。対象は親機のSpresense IMU、LIS3MDL、外付けGNSS。子機BNO085は親機に剛体固定されたIMUとは扱わない。
- ソース、既存検証レポート、保存済み検証結果を確認し、既存ホストテストを再実行した。今回の実機接続・書込み・給電指示・校正開始・時計変更はない。
- PC Wi-Fi切替、実機Web試験、SDフォーマット、既存ログ削除、隣接リポジトリ変更はしていない。親機温度・水圧・LCDは対象外。
- 今回は監査と機能提案だけで、ファームウェア・確定仕様は変更しない。以下の提案は未実装であり、校正値や精度の合格判定ではない。

## 判定

**現時点で、親機全体の姿勢・位置推定に必要な時刻同期と校正が完了しているとは確認できない。個別校正の実装はあるが、共通時刻・取付姿勢・位置オフセットを一体で扱う仕組みが不足している。**

| 項目 | コードで確認できたこと | 完了判定 |

| 親機GNSS PPS→親機時計 | PPS捕捉、RMC整秒ラベルとの連続対応、失効判定あり | 対応候補。絶対位相・遅延精度は未検証 |
| 親機時計→Spresense | 公称通信時間を補償した参考UTCの配信あり | 高精度同期ではない。残差・ドリフト未測定 |

## 実施・根拠

### 1. 時計は複数あり、UTC表示成立とセンサ同期成立は別

- [GNSS受信](../../include/gnss_link.h)はGP6 PPSを親機time_us_64で捕捉し、[gnss::Clock](../../common/gnss_nmea.h)が有効RMCの整秒UTCを直前PPSへ対応させる。連続3組、PPS周期999000〜1001000µs、受信時差2000〜800000µs、1.5秒の期限を検査する。ラベルの秒ずれや割込み遅延を外部基準で測った証拠ではない。
- [Spresenseリンク](../../include/spresense_link.h)は親機の選択済みUTCに公称最終byte受信までの時間を加えて送る。[Reference](../../common/spresense_control_protocol.h)は受信側の処理時刻をアンカーとして最大5秒保持する。[logger](../../firmware/spresense/logger/logger.ino)のlinkTaskはISR由来のbyte時刻をフレーム判定には使うが、parentReference.applyには処理ループのnowを渡す。処理待ちとタイマージッタは残る。往復計測による時計差・周波数差・不確かさの推定はない。
- 現行loggerはpps_connected=0を明示する。親機のGNSS/端末/RTCを参考として受け取り、親機GNSSへの直接PPS同期とは扱っていない。親子テザー用sync_ok/uncertainty_usもSpresense IMUの同期誤差を表さない。
- IMUは960Hz取得。[ImuBatch](../../firmware/spresense/libraries/AquaBeacon/src/ImuBatch.h)とloggerはsensor_timestamp_raw（19.2MHzカウンタ）とreceived_mono_us（read後のmicros）を保存する。差分による欠落検査はあるが、内部時刻の周回を展開し、ホスト時刻との倍率・オフセット・読出し遅延を推定する処理はない。microsのRTC粒度とサンプル時刻の正確さも別。
- Txxxxx.CSVの参考UTCアンカーとIxxxxx.CSVの読出し時刻から参考対応は作れるが、IMUサンプリング瞬間を親機GNSS時刻で保証するものではない。ライブラリにImuUtc.hが存在することだけで、現行loggerにPPS同期が組み込まれているとは判定しない。

### 2. 融合用ログには不足がある

- [LIS3MDL読出し](../../src/i2c_devices.cpp)は100ms間隔でdata-readyを調べ、lis_sample_ms=nowを保持する。これは読出し前の処理時刻であり、変換完了瞬間を捕捉したものではない。
- [main.cpp](../../src/main.cpp)のupdateSensorsは磁気の最新値をHealthへコピーし、saveHealthは通常1秒ごとに最新値を保存する。[Health構造](../../common/binary_log.h)にはLISのサンプル連番、専用取得時刻、生磁気値、磁気校正番号がない。10Hz取得の全サンプルを保存する専用磁気ストリームは確認できない。従って同じ磁気値の重複融合・観測時刻の取り違えを避けるログ拡張が必要。
- GNSSはNAV-PVT/RAWX/SFRBXを[UBXのまま保存](../../include/gnss_storage.h)しているので、受信機の観測エポックを後処理に利用する余地はある。一方、現在のGnssStatusのpvtUsは受信処理時刻で、融合用の観測時刻・位置速度・共分散をまとめた入力はない。5秒ごとのメタ情報を高精度の観測時計対応とみなさない。
- TIME_POSITIONのlatitude/longitudeは端末位置であり、親機GNSS測位の代用ではない。アンテナ型番・高さ設定はメタ情報で、IMUからGNSSアンテナ位相中心までの3次元オフセット補正ではない。

### 3. 個別校正はあるが、センサ間の校正ではない

- [Spresense校正](../../common/spresense_calibration.h)は6姿勢の静止条件・欠落・分散を検査し、加速度3軸のバイアス/倍率とジャイロ3軸バイアスを計算する。地球自転の鉛直成分を考慮する。IMU内部フラッシュには書かず、生値と補正値、calibration_generationを併記する。
- 取付回転、加速度/ジャイロの軸間非直交、ジャイロ倍率、温度依存性、ノイズ特性の同定はこの係数に含まない。単一IMUの校正ができても機体座標への変換は別途必要。
- [磁気校正](../../common/mag_calibration.h)は軸別min/maxのオフセットと倍率。軸間項を持つ完全なsoft-iron行列、IMUとの取付軸合わせ、傾斜補正、磁気偏角補正はない。[磁気保存](../../include/mag_console.h)とSpresense保存は独立しており、両者とCAD版を一つの校正セットとして記録・検証する仕組みもない。
- 組付け済み状態の磁気環境を確認する必要がある。送信・電源負荷で変化する磁気外乱は、静的なオフセット校正だけで吸収できると仮定しない。

### 4. 配線情報の不一致

- 今回のAGENTS.mdにはGP6=Spresense PPS入力、GP7=受信専用PIO UARTとある。
- [pins.h](../../include/pins.h)、現行コード、[半二重仕様](../../docs/spresense_halfduplex.md)、2026-10-11レポートではGP6=外付けGNSS PPS、GP7↔Spresense D03の半二重、D02未接続となっている。
- 隣接AquaBeacon/pcb/build_parent_main.pyも読取り確認した。GP6に対応する物理9番はGNSS_PPS、GP7に対応する物理10番はEVENT_MARKで、J_SPR1側の設計記述は親機→SpresenseのPPS/EVENT。設計資料だけでは実ハーネスを確定できない。build_child_main.pyも確認し、子機BNO系を親機IMU系と混同しない。
- 現在の実配線は未確認。古い指示を推測で上書きせず、受信専用の指示に反する送信やピン初期化を今回実行していない。次の同期実装・実機試験前に現物と指示を整合させる必要がある。

## 推奨する複数センサ校正機能（未実装の提案）

既存の個別校正を活用し、その上に「親機全体の校正セット」を設けることを推奨する。フュージョン開始前に次の状態を個別に表示し、未測定を0補正・合格と取り違えない。

| 機能 | 設定・記録する内容 | 検証方法 |
|---|---|---|
| 機体座標とCAD配置 | 原点・前/右/下などの軸規約、単位、sensor→body回転、基準点→各センサ位置、CAD版 | 既知の静止姿勢・正負の回転で符号と軸を確認 |
| 共通時刻 | 生時刻・読出し時刻・共通時刻、時刻源、時計変換の倍率/オフセット、有効期限・誤差推定・世代 | 共通イベント/利用可能な同期信号で残差とドリフトを実測。無断で配線追加しない |
| 個別校正 | IMU・磁気の既存係数、適用/保存/復元状態、校正世代、温度・取得条件 | 既存6姿勢/全方向回転と電源再投入後の再現性 |
| センサ間整合 | IMU↔磁気の取付軸、IMU↔GNSSアンテナ位置、必要なら観測遅延 | 既知姿勢/回転と移動ログで残差評価。十分な運動がない場合は同定不能と表示 |
| 校正セットの保存 | 機体・センサ識別、CAD版、係数参照、日時/時刻源、残差、適用可否 | CRC・新規版保存・読戻し・復元、CAD/センサ交換時の不一致検出 |
| 融合用ログ | 各新規観測の連番・サンプル時刻・生値・補正値・校正セット番号・品質 | 多周期のログ再生、欠落/重複/失効/再起動/時計周回の試験 |

CADから得られるのは主に位置と取付方向の初期値。センサ素子の実軸、GNSSアンテナの位相中心、組立公差を確認する必要があり、時刻遅延・IMUバイアス・磁気歪みはCADだけでは決定できない。IMUから離れた点の位置・速度や加速度を扱う際には、回転による位置差・回転加速度の影響も観測モデルに反映する。

実施順は、①現物配線と時刻経路の確定、②CAD配置/機体軸の登録と観測単位ログ、③個別校正・共通時刻の実測、④後処理で姿勢・位置融合と残差評価、⑤必要ならリアルタイム実装、が適切。全パラメータを一度の静置で自動同定する機能にはしない。許容時刻誤差・姿勢/位置精度は、用途の最大速度・角速度と要求精度から別途定め、未設定の間は精度合格にしない。

CAD提供時に必要なのは、機体基準点、各センサの原点/軸方向、GNSSアンテナ基準点、長さの単位、CAD版。筐体外観だけで取付回転を推定しない。単一アンテナGNSSの静止位置だけから機体方位は決まらず、IMU単独積分で長時間の位置精度を保証もしない。
