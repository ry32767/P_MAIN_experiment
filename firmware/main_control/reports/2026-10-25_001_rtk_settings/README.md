# RTK接続設定の事前保存・現地変更と学園都市の候補調査

## 前提
- 日付：2026-10-25。ユーザーの「学園都市」は神戸市西区・学園都市駅周辺と解釈。
- Pico 2 W / Arduino-Pico / PlatformIO。変更はこの作業フォルダ内。隣接の元リポジトリは変更していない。
- PCのWi-Fiは変更せず、通常のPCインターネット接続から公開キャスターを調査。
- 実機への書込み・電源操作・実機Web操作は実施していない。親子の実機識別を要する書込みは今回の範囲外。
- ピン割当、Spresense GP6/GP7の役割、親機温度/水圧/LCDの検証範囲は変更しない。

## 実施
- RTK画面に、基準局と認証の意味、アンテナ情報が任意である旨、事前設定・現地操作の手順を追記。
- 初期候補を `ntrip1.bizstation.jp:2101` / `3C722D56` に設定。候補を入力するボタンも追加。NTRIPユーザー名・パスワードは初期状態で空。個人のテザリング情報は未登録。
- `/api/gnss/config` で今回のみ適用し、`/save` で接続先・認証・Wi-Fi情報・配信先を親機SDへ保存、`/load` で保存値へ戻す機能を実装。
- 保存は親機SD認識済み、記録停止完了・測距停止・転送終了時だけ受理。入力を適用してから保存に失敗した場合は、今回のみ有効と表示。
- SDの二つの設定専用ファイル `AQ_NTRIP_A.cfg` / `AQ_NTRIP_B.cfg` に世代・版・CRC付きで保存。非最新側だけを書込み・同期・読戻し一致検査。途中書込み・破損時は有効な旧側へフォールバック。既存ログを削除・上書きせず、SDフォーマットもしない。
- 起動後最初のSDマウントで復元。先にWebで変更した値、SD復旧時の現在値は上書きしない。Wi-Fiは復元値で接続し、補正受信は手動開始。
- 既存の認証値をAPI・画面へ返さず、同一ホスト/ポート・明示的保持指定の空欄だけ既存値を使用。接続先変更時に旧認証を流用しない。Wi-Fi秘密も同一SSIDのときだけ保持。
- 保存ファイルは暗号化しない。ログ一覧から除外し、READ_LOGは大文字小文字を問わず `.cfg` を拒否。USB回収は既存の固定ログファイルのみで、設定は対象外。
- README、docs/spec.md、既存docs/gnss_rtk_ppk.mdを同時更新。docsのファイル増減はなし。

## 実測・PCで確認した結果
### 公開配信
- geortk.jp、rtk2go.com、ntrip1.bizstation.jp のソーステーブルを、NTRIP v1相当のGETで取得。
- ntrip1.bizstation.jp の候補 `3C722D56` は一覧の概略座標が北緯34.70度・東経135.00度、認証欄N、RTCM 3.2、2周波欄2。概略座標を正確な基準局座標として使用しない。
- 同局に認証ヘッダーなしで短時間接続し `ICY 200 OK` を受信。
- CRC24Q有効：1075/1085/1095/1115/1125 が各13件、1005/1230が各1件。取得区間でCRC不一致は0件。
- Galileo 1095の信号IDは2/15/23。RTKLIB信号表に従うとE1/E5b/E5aで、E1とE5aにはそれぞれ78セルの有効な搬送波値・正のCNRを確認した。GPS 1075はID2/10（L1/L2）でL5は当該区間にない。共通のGalileo E1/E5aがある候補として扱う。
- この結果はPCでの配信受信確認であり、親機による補正受信・RTK成立・精度の確認ではない。

### ビルド・ホストテスト
- 指定のPlatformIOで parent / child100 をビルド。両方成功。
- `python scripts/test_host.py` は既存のP_MAIN_experimentのvenvで実施し成功。通常PATHのPythonにはziglangが無かったため既存venvを使用した。
- 新規C++試験：保存/復元、二スロット、短い書込み、同期失敗、CRC破損、起動/復旧の上書き防止、世代番号の巡回、秘密の非公開、設定ファイル回収拒否。
- 実際のGNSS APIハンドラ試験：同一接続先の秘密保持、接続先変更時の消去、明示消去、不正/桁あふれポート拒否、記録/測距/転送/SD保存ガード。既存のfinishStop()がsdHealthy=false・sdReason=STOPPEDにする状態でも、正常に停止したマウント済みSDへ保存できることを追加確認。カード未挿入・障害状態は拒否。
- オフライン画面試験：保存値の読込み、編集中の入力保護、候補入力時のWi-Fi保持、適用→保存順、失敗表示、秘密の入力欄クリア、保存値への復帰、一覧/自動選択の反映。
- 既存のオフラインコンソール試験も成功：タブ・ラベル・一意ID・JavaScript構文・色コントラスト。

## 未検証
- 親機実機の設定書込み・再起動/電源断後の保持、カード抜差し、実負荷下のSDファイルシステム耐性。
- 親機のテザリング接続、キャスター接続、RTCM転送、Float/Fixed成立、学園都市現地の稼働と位置/時刻精度。
- 実機Web画面、公開GitHub Pagesの更新/公開。今回更新した画面は親機内蔵版のソース。
- 基準局の座標精度・基準系の妥当性・長期稼働。ソーステーブルは利用時に変わりうる。
- RINEX変換・PPK解算。アンテナ情報は従来どおり今回の記録のみで、接続設定の保存対象には含めない。

## 現地での確認手順
1. 更新した親機ファームウェアを書き込む場合は、先にUSBシリアル番号と役割応答で親機と識別する。
2. ユーザーが親機Webを開き、テザリング情報を入力。記録・測距・転送を停止して「入力した設定を適用してSDへ保存」。成功表示を確認。
3. 安全に記録を停止して再起動し、保存設定の読込み表示を確認。登録済み秘密は再入力しない。
4. テザリングを有効にして「この局でRTK補正を開始」。補正件数・解の状態を確認し、実験記録は必要に応じて再開する。
5. 現地で別局/別Wi-Fiへ変更し、今回のみ適用と、保存設定への復帰を確認する。
6. 精度の評価は別途既知点・基準時刻等で実測し、Fixed表示だけで合格としない。
