# 親機GNSSのRTK・PPK運用

## 事前設定と現地での操作（2026-10-25）

基準局は「位置の誤差を補正するデータの配信元」。NTRIPユーザー名・パスワードは補正サービスの利用情報で、WindowsやAquaBeaconのアカウントではない。無料でも認証が必要なサービスはある。アンテナ型番・高は親機側の記録用情報で、空欄でも受信できる。高さを入力するときは基準点とアンテナ側の測定位置を実験メモへ残す。

### 出発前
1. ユーザー自身が親機コンソールの「時刻・位置」を開く。PCのWi-FiはCodexから変更しない。
2. 「接続の準備・現地で設定を変更」を開く。初期候補は神戸市西区の学園都市駅周辺を想定した `ntrip1.bizstation.jp` / ポート `2101` / 配信先 `3C722D56`。補正サービスのユーザー名・パスワードは空欄で接続できた。別の設定を使用した後は「神戸・学園都市周辺の無料局候補を入力」で入力欄へ戻せる。このボタンだけでは設定は適用されない。
3. 現地で使うスマホテザリングのWi-Fi名・Wi-Fiパスワードを入力する。補正サービスのパスワードとは別物。
4. 「実験終了・親子の記録を停止」と「測距送信を停止」で記録・測距を止め、ログ転送の完了を待つ。
5. 「入力した設定を適用してSDへ保存」を押し、SD保存・読戻し確認の成功表示を確認する。失敗時は保存済みとは扱わない。適用だけ成功して保存が失敗した場合、その設定は今回のみ有効。

保存対象はサーバー・ポート・NTRIP認証・Wi-Fi名/パスワード・配信先名。同じ親機SDがあれば再起動後の最初のSDマウントで読み込む。補正受信は自動開始しない。アンテナ情報は従来どおり今回の記録用で、接続設定の保存対象外。SD内の接続情報は暗号化されない。画面/APIから既存の認証値は読み出せず、接続情報ファイルはログ回収の対象外。

### 現地
1. 登録したスマホテザリングを有効にし、親機を起動する。
2. 「SDの保存設定を読込み済み」を確認し、「この局でRTK補正を開始」を押す。
3. 「補正受信中」・受信件数の増加と、「RTK Float／Fixed」を別々に確認する。補正到着やFixedの表示だけで位置精度を合格にしない。
4. 実験タブから必要な記録を開始する。保存操作のため停止した記録は自動再開しない。

接続先は現地でも同じ画面で変更可能。「接続設定を適用（今回のみ）」はSDを変更しない。「SDに保存した設定に戻す」は現在の補正受信を止め、保存値を読み直す（再開は開始ボタン）。登録済みパスワードを再入力しなくてもよいように、同じ接続先で空欄の場合はチェック欄に従って既存値を保持する。接続先ホスト/ポートを変更した場合、旧サービスの認証情報は引き継がない。Wi-Fi名変更時も旧Wi-Fiパスワードを引き継がない。認証不要に変更する場合は「登録済みの認証情報を使う」のチェックを外して適用する。

別局は「基準局一覧を取得」後に選ぶか、配信先名を直接入力する。選択/自動選択だけではSDに保存されないため、次回も使う場合は記録・測距を止めて保存する。「100km以内の最寄り候補」は親機の測位が必要で、L5・利用権限・局品質までは保証しない。NEO-F9PはL1/L5なので、共通の観測信号を配信する局を使う。「2周波」だけでL5対応と判断しない。

### 学園都市周辺の候補を確認した範囲
2026-10-25に通常のPCインターネット接続から公開ソーステーブルを取得し、上記配信先へNTRIP v1・認証なしで短時間接続した。`ICY 200 OK` とCRC有効のRTCMを受信。Galileo MSMの信号欄にE1/E5aがあり、GPS MSMはL1/L2でL5は確認できなかった。受信機と共通のGalileo信号がある候補として設定し、NEO-F9PでのRTK成立や現地精度は未検証とする。稼働状態・内容は変わりうる。

根拠：[Drogger運営元の料金・移動局アクセス案内](https://drogger.hatenadiary.jp/entry/ntripCaster)、[Drogger運営元の一般NTRIPクライアント設定案内](https://drogger.hatenadiary.jp/entry/2025/02/05/200447)、[RTKLIBのMSM信号表](https://github.com/tomojitakasu/RTKLIB/blob/master/src/rtcm3.c)。前者のNEAR方式の認証不要説明と、今回の個別局への無認証接続実測は区別する。調査・検証の詳細は[レポート](../reports/2026-10-25_001_rtk_settings/README.md)。

## PPKデータ
親機SDの実験記録と一緒に、毎回新規UBX・RTCM3・JSONLを作成する。RAWXとSFRBXの保存数、UART/UBXエラー、保存欠落を確認する。終了後に「ログ・SD」の親機一覧から3ファイルを回収。基準局側の同じ観測時間のデータも別途用意する。補正ストリームのRTCMファイルだけで必要な観測・航法が揃うとは限らない。

USBでの回収例（実機識別済みCOM6を使用。出力先は新規ファイル）:

```
python scripts/dump_log.py --port COM6 --gnss ubx --out reports/raw/rover_new.ubx
python scripts/dump_log.py --port COM6 --gnss rtcm --out reports/raw/base_stream_new.rtcm3
python scripts/dump_log.py --port COM6 --gnss meta --out reports/raw/session_new.jsonl
python scripts/verify_gnss_ppk.py reports/raw/rover_new.ubx --output reports/raw/rover_new_audit.json
```

RTKLIB convbinを用意した場合:

```
python scripts/verify_gnss_ppk.py reports/raw/rover_new.ubx --convbin C:/RTKLIB/convbin.exe --rinex-dir reports/raw/rinex_new
```

元UBXは保持し、既存rover.obs/rover.navの上書きを拒否する。受信機はL1/L5のため、使用するRTKLIB版・設定も信号を扱えることを確認する。基準局観測と精密な局座標、アンテナ情報を揃えた後にPPK処理を行う。今回PPK解算と精度測定は実施していない。

仕様と制限は[spec.md](spec.md)「RTK・PPK対応」を参照。
