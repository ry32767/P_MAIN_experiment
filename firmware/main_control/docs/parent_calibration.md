# 親機校正セット・PPS基準サンプル時刻

## 配線と同期

親機J_SPR1の3本は **1番=PPS、2番=通信、3番=GND**。隣接AquaBeacon/pcb/build_parent_main.pyではGNSS_PPSから100Ωを経由して1番へ接続する。親機GP6は外付けGNSS PPS入力、GP7は既存D03通信を維持。Spresense拡張D02を入力専用PPSとして追加し、共通GND・JP1=3.3Vを前提にする。ユーザーがXH左端からSpresense D02への接続を確認し、実機でも親機/SpresenseのPPS検出・UTC対応が成立した。AGENTS.mdの旧記述もこの構成へ更新した。未検出時は未同期とする。

SpresenseはPPS割込みでmicrosを捕捉する。親機はラベル済みGNSS PPSのUTCと送信時の経過時間を既存D03フレームで送る。公称受信時間はパルス番号の選択にだけ使用し、位相はSpresenseで捕捉したPPSに置く。受信byte時刻にも各MCUの実際の単調時計をISRで保存する。

PPS履歴8件、候補の公称時刻差100ms以下、周期990000〜1010000µs、UTC秒差とパルス番号差が一致する独立した3組で対応成立。ラベルの間隔は最大10パルス。定期照会は通信往復と待機で数秒かかるため、ラベルを毎秒受ける条件にはしない。対応アンカーは6秒、直近PPSは1.5秒で失効。異常周期・欠落・キュー溢れ・GNSS以外のラベルで成立を解除し、端末時計/RTCからPPSのUTCを作らない。これらの閾値は精度保証ではない。

IMUの19.2MHzカウンタを64bitへ展開し、読出し遅延の小さい点から倍率・オフセットを推定。PPS間隔からSpresense時計の倍率も補正してサンプル推定時刻をUTCへ換算する。**IMUサンプリング回路自体の位相をPPSで駆動・リセットするハードウェア同期ではない。** 通常SDK取得APIにその操作はなく、固定読出し遅延・内部遅延は未測定。`time_uncertainty_us=4294967295`（未測定）を維持し、精度合格にしない。開始後50msはSony仕様に従い保存・校正から除外する。

## 各サンプルの記録

Spresense Ixxxxx.CSVはschema=3。従来の生値・補正値・個別校正番号を残し、CRCの前へ追加する。

| 列 | 意味 |
|---|---|
| seq / received_mono_us / sensor_timestamp_raw | 起動中の取得連番 / read後の単調時刻 / 内部生カウンタ |
| sensor_ticks_unwrapped | 周回展開したカウンタ。再推定はclock_generationで区別 |
| sample_mono_us / sample_utc_us | 推定サンプル単調時刻 / PPS基準UTC。不成立は0 |
| clock_generation / pps_count | 時計再推定の世代 / 直近PPS番号 |
| parent_set_generation / parent_session | 親機セット番号 / 配信元親機の起動セッション |
| time_quality | 0=推定不可、1=内部時計→ホスト時計のみ、2=PPS対応UTCへの換算も成立 |
| time_uncertainty_us | 4294967295=精度未測定 |

失効行にも生値・連番・読出し時刻を残す。カウンタ重複、大差分、1秒超の取得停止などで再推定する。周波数の更新で現在位相を飛ばさず、読出し時刻の下側包絡へ位相を合わせる。FIFO連続読出し等で単調な推定時刻を出せない行は0/quality=0として保留し、毎回2秒の準備状態へ戻さない。正常周回では継続。時計世代をまたぐ区間を同一時計として結合しない。Txxxxx.CSVにもPPSアンカー単調時刻/UTC・番号/周期/対応状態・親機セット番号/sessionを追記する。

親機P_MAIN_HEALTH_RANGEログは1秒ごとのHEALTHとは別に観測レコードを追加する。

- kind10 MAG_OBSERVATION：10Hzの新規観測ごとに連番、I2C読出し開始/終了、終了時の参考UTC、生値/補正値/配置設定済みなら機体軸値、有効性、個別校正/セット番号。記録停止中も取得連番は進む。変換瞬間のDRDY割込み時刻ではなく、不確かさは未測定。
- kind11 CALIBRATION_SET：新規親機ログの先頭に適用セットの全配置・識別・校正参照を保存。未保存なら出力せず、観測のセット番号は0。
- kind12 GNSS_OBSERVATION：NAV-PVTごとの連番、受信完了時刻/参考UTC、受信機の観測エポックiTOW、位置/速度/精度推定/状態、セット番号。受信時刻と観測エポックを区別する。既存UBX保存は維持する。

位置オフセットとIMU/GNSSの取付回転はセットに保存し、後処理で参照できる。新たな姿勢・位置フィルタやレバーアーム補正済み航法出力を追加したものではない。[バイナリ仕様](binary_log.md)のデコーダで種類別CSVへ分離でき、旧ログも読める。

## センサー校正タブ（2026-10-25 簡略化）

個別校正と校正セットは初期状態で閉じた項目にし、必要な機器だけを開く。BNO085は「子機 BNO085」と明記する。

1. Spresense IMU・親機磁気の項目を開き、個別校正を実施・保存・終了する。
2. 「ログ・SD」で親機とSpresenseの記録を停止し、測距も停止する。
3. 「親機校正セット」を開き、「現在の個別校正をセットに保存」を押す。
4. 保存番号・個別校正の一致を確認し、「ログ・SD」から必要な機器の記録を再開する。

セット名・CAD版・機体/センサ識別名・位置・姿勢の入力欄はコンソールから削除した。校正番号だけを更新し、既存の配置・識別情報は保持する。初回保存では未知の配置を既定値のまま未確認として保持し、位置を確認済みとは扱わない。5秒の通信失効後は状態不明・保存禁止。

「個別校正 一致」は適用中のIMU・磁気校正番号が保存値と一致し、IMU状態も新しいこと。総合準備完了や精度合格ではない。個別校正をやり直したらセットも保存し直す。子機BNO085は別機体のためこのセットには含めない。

## 保存・API・互換性

親機SDへP_MAIN_CALSET_00001.tmp等を排他的に作成し、version=1・376byte・CRC32、同期・読戻し一致後に未使用の.binへ確定する。失敗した.tmpは残して復元対象外とし、以前のセット・ログを上書き/削除しない。起動/再マウント時に有効な最大番号を復元。壊れた.binがあればエラー表示し、以前の有効セットがあればそちらへ戻す。個別校正の保存先は従来どおり各機のSD。

GET /api/parent-calibration、POST /api/parent-calibration/save。POSTは既存Origin・X-Aqua-Control検査付き。コンソールの本文はreference_only=1で、個別校正参照のみ更新する。既存の配置・識別情報は保持する。互換APIでは従来のname/cad/body、i=0..2のs{i}id/s{i}known、j=0..6のs{i}{j}（XYZ、wxyz）も引き続き受け付ける。停止/カード/入力条件不成立は409。Spresense未取得時はIMU校正番号0の下書きとして保存する。

D03フレームversion=3・128byteは維持。要求payload[25]=0xA3、[26..33]=PPSラベルUTC、[34..41]=送信時ラベル経過µs、[46..49]=セット番号、[50..53]=親機session。応答nav.satellites=0xA3が拡張マーカー、nav.lat/lonはPPS番号/周期の診断領域（GNSS測位ではない）。payload[66]はbit0=参考UTC、bit1=PPS検出、bit2=PPSとUTC対応、bit3=IMU時計推定準備完了。元の参考UTC/SD/個別校正診断を維持し、旧版はPPS診断未取得と表示する。

**IMU共有バッチABIは版3。親機とSpresense MainCore/logger・SubCore1/formatterの両方を更新する。** 旧親機はPPSラベルを配信せず、旧Spresenseは新しいサンプル時刻列を生成しない。

根拠：[Sony SDKガイド](https://developer.sony.com/spresense/development-guides/sdk_developer_guide_ja)のIMUカウンタ/API、[Sony Introduction](https://developer.spresense.sony-semicon.com/development-guides/?lang=ja&page=introduction)の開始後50ms無効データ。[今回の検証記録](../reports/2026-10-25_003_parent_calibration_set/README.md)。

## 実機で追加確認した条件（2026-10-25）

- 実IMUタイムスタンプは理論の20000tickへ完全一致しない。保存済み実CSV2035行は差分15594〜20686tickで、完全一致条件では全てを校正中の欠落と誤判定する。取得時の欠落検査と校正の欠落入力を共通化し、理論周期の1/2〜3/2内を正常範囲とする。重複・短すぎる差分・欠落相当の大差分は拒否する。これは時刻精度の合格条件ではない。
- 磁気は10Hzの変換に対し10ms間隔でdata-readyを確認する。STATUS_REGの上書き検出を観測に保存し、内部データ欠落を連番だけで判定しない。
- SD保存の再開は準備中にUSB応答が遅れる場合がある。検証ツールは行の途中で受信期限に達しても、次の受信と結合してJSONを解析し、実際の記録状態を照会する。
- USBの安全停止後BはArduino-Pico標準のrebootを用い、再起動要求後にウォッチドッグを給餌し続けない。
- 実機更新・PPS・校正セット保存/復元・公開結果と制限は[配備レポート](../reports/2026-10-25_004_pps_deployment/README.md)を参照。

2026-10-25追記：親機core0のSD再準備中も、core1が保持する最新のGNSS PPSアンカーからSpresense用UTCとPPSラベルを直接生成する。古いUI/保存用UTCスナップショットの失効でセンサ側同期を解除しない。有効なGNSSがない場合の端末/RTCフォールバックと、明示GPS無効化の診断操作は維持する。


## 2026-10-26 校正の実施順と時刻記録
センサー校正タブを「準備 → 親機Spresense IMU → 親機LIS3MDL → 子機BNO085 → 親機校正セット → 復元確認・記録再開」の順にする。子機校正は親機校正から独立し、子機未使用時は省略できる。既存の操作ID・停止/接続ガード・保存形式を保持し、自動実行や完了判定を追加しない。

通常記録ではSpresenseにサンプル推定単調時刻/PPS対応UTC/品質/校正番号、子機BNOに取得単調時刻/センサ時刻/参考UTC/時刻源がある。一方、校正中は対象機器の通常記録を停止するため、校正動作の時刻付き波形・各姿勢の開始終了は永続記録しない。個別IMU/磁気係数とBNO DCD保存にもアプリ管理の校正UTC履歴はない。親機セットcreatedUtc/utcSourceはセット作成時の参考UTC/時刻源であり、個別校正の実施時刻ではない。無効なUTCの扱いは既存ストア仕様に従う。

カメラIMUとの照合用の動きは、校正後にカメラと対象機器の通常記録を再開して別途行う。同一機体への固定、サンプル時刻付きカメラIMUの取出しが前提。親機/子機は各々のカメラと照合する。自動照合・カメラ連携・同期精度保証・校正専用波形記録は今回追加しない。

受け入れ条件：画面DOMの順番が準備/IMU/磁気/BNO/セット/再開であること、既存操作IDと未接続ガードを保持すること、通常ログと校正中の記録有無を区別すること。ホスト試験と親子ビルドで検証する。実機Webはユーザーが確認し、PC Wi-Fiを切り替えない。


時刻合わせの技術的参考：[ETH Kalibr Camera IMU calibration](https://github.com/ethz-asl/kalibr/wiki/camera-imu-calibration)。同資料は画像とIMUの時空間校正を扱う。今回のカメラ内IMUと機体IMUの波形照合は未実装で、同ツールがカメラ機種のデータへそのまま使えるという意味ではない。


### 2026-10-26 校正中の判定フィードバック
- Spresense IMUは6姿勢の未測定/測定中/やり直し/測定条件通過と現在姿勢の進捗を表示する。最終の係数整合性チェック通過、保存失敗、復元失敗を区別する。通信が新しくてもIMU未取得なら現在進捗を隠して取得確認を案内する。
- 姿勢/重力範囲/回転/急変/非数/取得間隔や欠落/点数不足/区間分散の既存拒否条件から理由ビットを生成する。閾値・校正数学は変更しない。直近の拒否理由は次の拒否または姿勢選択まで保持するため、測定継続中の理由は履歴として表示する。回数は条件外サンプル・測定区間の回数で、ユーザーの測定試行回数ではない。
- D03のversion=3/128byteを維持。PPS診断マーカーnav.satellites=0xA3、position_validなしの応答でのみ、未使用nav.altitude_mmをuint32として0xCA000000 | (min(resets,65535)<<8) | rejectionへ割当てる。これは標高ではない。旧親機は無視し、新親機はマーカーがない旧Spresenseを詳細診断未取得とする。nav.flags、PPS番号/周期、UTC、SD診断領域は維持する。
- /api/status.spresenseへcalibration_diagnostics、calibration_rejection、calibration_rejectionsを追加。拒否bitは1=欠落/間隔、2=非数、4=回転、8=重力範囲、16=姿勢、32=急変、64=点数、128=分散。回数の65535は飽和し「以上」を表示。診断フラグは通信失効時false。
- 磁気のAPIへfit_evaluated/radius_matchを追加し、既存計算結果から評価可能性と平均半径の整合を返す。画面は接続/鮮度/時間/点数/XYZ幅/8方向/飽和/半径ばらつき/半径整合を表示。幅不足時の初期CV=0を成功扱いしない。最終保存可否は装置のreadyを使い、ブラウザーの再計算で保存を許可しない。数値と保存情報は同じ項目内の詳細へ移す。5秒間の画面更新失効で案内と条件を不明へ戻す。
- BNOは加速度/ジャイロ/磁気の不足に応じて姿勢変更・静止・多軸回転を案内する。全て中以上でも装置readyになるまで5秒継続の判定待ちとし、ブラウザーで合格時刻を推測しない。通信失効・未知の状態値は未確認。
- 判定通過・保存可能・保存応答は実測精度の合格ではない。独立した基準比較、カメラ同期、校正時波形の保存は今回追加しない。操作順と既存の保存/停止/未接続ガードは維持。
- 受け入れ条件：実際の拒否入力から正しい理由を生成／Spresenseエンコーダと親機デコーダ間で往復／旧データと本来の位置データを誤解釈しない／未評価CVを成功表示しない／進捗・不足・保存可能・保存失敗・失効の画面試験／親子とSpresense両コアのビルド。未測定の精度は合格としない。
